<p>A user who forgot their password used to need somebody with a console. This release adds password reset and email verification: signed links in the framework, and the pages and mail that send them in the skeleton. Everything in the framework is a new class, a new interface or a new optional parameter, so it is a patch.</p>

<h3>Links that spend themselves</h3>

<p><code>PasswordResetTokens</code> and <code>EmailVerificationTokens</code> each have <code>create($user)</code> and <code>resolve($token)</code>. A token is signed with <code>APP_KEY</code> and carries a digest of the value it is bound to: the password hash for a reset, the address for a verification. When that value changes, the link stops working. No table stores the tokens, so there is nothing to clean up. Both are built on <code>SignedToken</code>, which is public for links of your own. <code>AUTH_RESET_TTL</code> (an hour) and <code>AUTH_VERIFY_TTL</code> (a day) set how long each lasts. <a href="/docs/auth.html#links">Authentication</a> covers the design.</p>

<p>Email support is opt-in. A user implements <code>HasEmailInterface</code>, and a provider implements <code>EmailUserProviderInterface</code> and passes <code>EmailUserProviderContractTestCase</code>. <code>FakeUser</code> takes an address as a third, defaulted argument, and <code>ArrayUserProvider</code> can find a user by address. <code>auth</code> now requires <code>psr/clock</code>, which <code>core</code> already required.</p>

<h3>In the skeleton</h3>

<p><code>/forgot-password</code> gives the same answer whether or not the address has an account. It is throttled per client with a visible 429 and per address silently. A token moves from the link into the session on the first request, so it never reaches the activity log. A signed-in user whose address is unverified sees a banner in the admin that sends a link. The admin shell has a new <code>$banner</code> slot above the frame for it. <code>make:user</code> takes an address after the username, and the users table requires one.</p>

<div class="note">
  <span class="label">An app started from an earlier skeleton</span>
  <p>The skeleton added <code>email</code> and <code>email_verified_at</code> to its create-table migration rather than in a new one, so an existing database does not get them. Add them with a migration of your own and backfill an address for each account before making the column <code>NOT NULL</code>.</p>
</div>

<p>Reset and verification dispatch no events yet, and a verification link is only sent when somebody asks for one. Both wait for a queue, which is also what will close the timing gap left by sending mail within the request.</p>
