<p>Seven findings from reviewing <a href="0.4.1.html">0.4.1</a>, outside the rate-limiting gate. Each one is a rule that was stated in one place and not held in another.</p>

<div class="note warn">
  <span class="label">Breaking</span>
  <p><code>PhpView::__construct</code> moves the CSP nonce from an optional sixth parameter to a required second one, and <code>Template::__construct</code> with it, so <code>new PhpView($path, $csrf)</code> now passes a guard where a nonce is required. The break is at construction, on purpose: the application boots or it does not, rather than failing the first time somebody opens a screen. The release gate could not see it &mdash; that is the open item this release left behind, and <a href="0.5.2.html">0.5.2</a> closed it.</p>
</div>

<h3>The CSP extension</h3>

<p><code>hx-csp</code>&rsquo;s stolen-nonce scrub was whitespace-bypassable: it matched <code>nonce=</code> with no space, but HTML allows <code>nonce = "&hellip;"</code>, and anyone holding the nonce controls those bytes. It matches the attribute by <em>name</em> and compares the value now &mdash; whitespace either side of the <code>=</code>, all three quotings and a mixed-case name are one attribute to the parser and one match here. Same hole, second spelling: <code>hx-nonce="&amp;#114;4nd0m&hellip;"</code> also walked past a byte comparison, and the parser decodes it back into the real nonce on the way into the DOM, so a value that is not base64 is dropped outright.</p>

<p>Its gate was also not fail-closed for an element with no <code>hx-*</code> of its own: the check only blocked when the cleanup had removed something, so a boosted element passed ungated. The refusal and the cleanup are separate things now &mdash; an element can be blocked for what it inherits. The nonce is read with htmx&rsquo;s own attribute lookup, inheritance included, so an element boosted from an ancestor is nonced from that same ancestor: what made the element htmx&rsquo;s is what has to vouch for it.</p>

<p>23 cases in <code>hx-csp.test.mjs</code> load and register the real extension and drive it end to end, on node&rsquo;s own runner with no <code>package.json</code>. Against the old scrub and the old gate, ten of them fail.</p>

<h3>The rest</h3>

<dl class="defs">
  <dt>Every shipped admin view calls <code>cspNonce()</code></dt>
  <dd>Which threw when the view was built without one, so an application on <code>hydrakit/admin: ^0.3</code> that updated got a 500 on every admin screen. Hence the required parameter above.</dd>

  <dt>The shipped-views contract covers the skeleton too</dt>
  <dd>The admin package required an <code>hx-nonce</code> beside every htmx attribute across its own views; <code>views/</code> had no equivalent, so a skeleton template that forgot one broke silently under the policy. Duplicated rather than shared on purpose: an application cannot reach into a package&rsquo;s test suite, and this is a file the skeleton&rsquo;s users own and will extend. Both blank attribute <em>values</em> before looking for attribute names now &mdash; the scan was reading the htmx-config meta tag as an htmx element and demanding a nonce of it.</dd>

  <dt><code>SecurityHeadersMiddleware</code> takes its set as an argument</dt>
  <dd>It held a hardcoded three-header constant and sent <code>X-Frame-Options: SAMEORIGIN</code> alongside CSP&rsquo;s <code>frame-ancestors</code>. <code>DEFAULTS</code> and <code>WITH_CSP</code> name the two that matter, and the application picks between them on whether CSP is enabled &mdash; because CSP can be switched off and the header is what carries the rule when it is.</dd>

  <dt>The error handler stays 5th, and the docblock was the defect</dt>
  <dd>It claimed to be outermost. The four middlewares outside it stamp headers on the way back <em>out</em>; move the boundary above them and the response rendered for an error becomes the one response in the application carrying no policy and no security headers. What that costs is a throwable from those four escaping, and the kernel&rsquo;s panic path already answers that with a logged plain-text 500.</dd>

  <dt><code>UserSource</code> ignored <code>AUTH_HASH_COST</code></dt>
  <dd>It coincided with bcrypt&rsquo;s default of 12 on PHP 8.5, so the drift was latent rather than live &mdash; which is exactly how a setting stops reaching somewhere without anyone noticing. It takes <code>HasherInterface</code> and calls <code>hash()</code> now.</dd>

  <dt>Debug is opt-in rather than opt-out</dt>
  <dd>The compose base is production-shaped: the build mode defaults to prod and <code>prod.ini</code> is what gets mounted, with the dev overlay swapping in the other two. The Dockerfile&rsquo;s own default matches, so a plain <code>docker build</code> does not ship a debugger, and <code>.env.example</code> ships <code>APP_DEBUG=false</code>.</dd>
</dl>
