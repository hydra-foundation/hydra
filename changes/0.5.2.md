<p>A release about the harness rather than the framework. Additive only: the framework suite went from 858 tests and 1717 assertions to 1050 and 2101, and every package gained a measured floor it had never had.</p>

<h3>Contract cases ship as public API</h3>

<p>They live in each package&rsquo;s <code>src/Testing</code>, not under <code>tests/</code>, and that is the whole reason they reach anyone: Composer ignores a dependency&rsquo;s <code>autoload-dev</code>, so a case under <code>tests/</code> ships in the archive and cannot be autoloaded by the application that installed it. Proven rather than assumed &mdash; the skeleton&rsquo;s own error renderer and user repository extend the framework&rsquo;s cases across the two repositories, through the real autoloader.</p>

<p>Seven new ones joined <code>StoreContractTestCase</code>: session, hasher, user provider, connection, error renderer, server-request provider and view. <code>UserProviderInterface</code> is the one that most needed it &mdash; auth owns no user storage, so it is the seam the framework ships and never fills, and every application writes it against its own schema with nothing to check it against.</p>

<p>What they turned up: the native session store had never been held to the flash, null-as-removal or <code>clear()</code> halves of its contract; <code>NativeHasher::hash()</code> lets <code>password_hash</code>&rsquo;s <code>ValueError</code> out on a password carrying a NUL byte, which a form post can carry &mdash; pinned in a test rather than swallowed, since keeping one out is the application&rsquo;s validation to write and nothing said so before.</p>

<h3>Coverage is measured at all</h3>

<p><code>bin/coverage.php</code> reads a clover report and holds each package to a floor recorded in <code>coverage.json</code> &mdash; per package, not one number for the tree, because <code>http</code> and <code>admin</code> are two thirds of the source and would carry the average on their own.</p>

<p><strong>87.26%</strong> of lines with <code>requireCoverageMetadata</code> on, which is the honest number and not the 93.11% the first run reported before every test had to name what it covered. <code>event</code> falling from 100% to 57.89% under that flag is the whole argument for it: its 19 lines were being walked by other packages&rsquo; tests and credited to nobody&rsquo;s intent. <code>packages/cache/src</code> was missing from the source list entirely &mdash; the counter store the rate limiter rests on would have read as uncovered and uncounted the first time coverage ran.</p>

<h3>Mutation testing over three packages</h3>

<p>Coverage says a line ran, not that a test would notice it changing. Infection runs over <code>validation</code>, <code>throttle</code> and <code>http</code> &mdash; fifteen seconds for the three, which is the difference between a tool that runs and one that does not &mdash; gated on <code>minCoveredMsi</code>. Started at 87% covered MSI, now 89%.</p>

<p>Real defects, not test-shape complaints. <code>TrustedProxies</code> had only ever been tested on byte-aligned prefixes, and its entries arrive out of an environment variable with the space after the comma still on them: a range that parses wrong trusts a wider block than was written, and everything inside it can then claim to be any client it likes. <code>RateLimiter::hit()</code> was never called directly, leaving its visibility and the <code>max(1, &hellip;)</code> that keeps <code>Retry-After</code> off zero unprotected. <code>ThrottleConfig</code>&rsquo;s constructor defaults were untested, <code>enabled</code> included. A test named for multibyte awareness used only ASCII.</p>

<p>Infection lives in <code>tools/infection/</code> rather than in <code>require-dev</code>: it needs PHP 8.3 and the framework supports 8.2, and a dev tool must not decide what the library can be installed on. Its bundled Composer plugin is declined rather than enabled &mdash; it only auto-registers optional extensions, none of which are used, so there is no reason to grant install-time code execution, in CI least of all.</p>

<h3>The skeleton suite now runs against the tree being changed</h3>

<p>The skeleton&rsquo;s CI installs from its committed lock, so the eight integration flows &mdash; the only end-to-end coverage in the project &mdash; were verifying <em>released</em> code. A job now checks out both repositories at the PR&rsquo;s ref and installs with the development Composer file, in both directions. A kernel change that breaks boot was discoverable only after the tag.</p>

<h3>The release gate could not see a signature change</h3>

<p><code>bin/api-surface.php</code> recorded names only, so a parameter added, reordered, retyped or promoted from optional to required left the name untouched and the comparison reported nothing removed. <a href="0.5.0.html">0.5.0</a> was exactly that shape, and <code>bin/release.sh 0.4.2</code> would have shipped it as a patch.</p>

<p>Signatures on the line then made every appended optional parameter read as a removal, which <code>comm</code> cannot tell from a break. The comparison moved to <code>bin/api-diff.php</code>, which forgives that one shape: a gate that cries break on a compatible change gets <code>--minor</code> by reflex, which costs the same as not having a gate. Checked against v0.4.1 &mdash; the old tool reports 0 removals, the new one reports the two that are really there. <code>tests/Unit/ApiSurfaceTest.php</code> drives both scripts as subprocesses over a fixture tree, with the breaking and compatible sets as data providers so the next edit has to keep answering all of them.</p>

<h3>Smaller</h3>

<ul>
  <li>Strictness both repositories had left off: <code>failOnRisky</code>, <code>failOnNotice</code>, <code>beStrictAboutOutputDuringTests</code>, <code>displayDetailsOnSkippedTests</code> and <code>beStrictAboutChangesToGlobalState</code> &mdash; cross-package leakage through <code>putenv()</code>, <code>$_ENV</code> and statics is the suite&rsquo;s real failure mode, and randomised order finds it by luck where this finds it by construction. PHPStan analyses the packages&rsquo; own tests now too.</li>
  <li>Five <code>sleep()</code> calls &mdash; nine seconds of wall clock, and the only tests of window expiry &mdash; are a clock seam now. Redis&rsquo;s TTL genuinely needs the server and keeps its sleep.</li>
  <li>Eight classes were not named in any test in either repository. They are now.</li>
</ul>
