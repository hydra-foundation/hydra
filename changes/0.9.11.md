<p>Until now, the only way to sign in was a session cookie, which only a browser carries. A script, a mobile app or a frontend on another origin had no way in. Now a user can make a personal token in Settings and send it as <code>Authorization: Bearer</code>. It works on the API and nowhere else. It is stored only as a hash, it skips both the session and the CSRF check, and a password reset revokes it. CORS lets another origin&rsquo;s pages call the API. It is off until you name that origin.</p>

<p>Every symbol here is new and every new argument is optional, so this is a patch. One binding moved; it is covered under Upgrading.</p>

<h3>Upgrading</h3>

<p><code>GuardInterface</code> now resolves to <code>RequestGuard</code>, which wraps the same <code>SessionGuard</code> it used to resolve to. Anything that asked for <code>GuardInterface</code> works as before. Code that asked for <code>GuardInterface</code> and then checked it was a <code>SessionGuard</code> should ask for <code>SessionGuard::class</code> directly. Nothing changes for a request with no Bearer header.</p>

<p>To add tokens to an application built on the skeleton:</p>
<ul>
  <li>Run the <code>api_tokens</code> migration.</li>
  <li>Bind an <code>ApiTokenStoreInterface</code>. The skeleton&rsquo;s <code>ApiTokenRepository</code> is ready to copy.</li>
  <li>Add <code>AuthenticateBearerMiddleware</code> after <code>StartSessionMiddleware</code>, and <code>CorsMiddleware</code> above <code>ErrorHandlerMiddleware</code>.</li>
  <li>Have your unauthenticated-redirect middleware rethrow under <code>/api/</code>.</li>
  <li>Copy the <code># CORS</code> block from <code>.env.example</code>.</li>
</ul>

<h3>API tokens</h3>

<p><code>ApiTokens</code> issues <code>hyd_</code> tokens and authenticates them. <code>ApiTokenStoreInterface</code> is yours to implement, and <code>ApiTokenStoreContractTestCase</code> tests it. <code>AuthenticateBearerMiddleware</code> accepts a token under <code>/api/</code> and answers a 401 anywhere else. <a href="/docs/auth.html#api-tokens">API tokens</a> has the details. In the skeleton:</p>
<ul>
  <li><code>GET /api/v1/me</code> returns the caller.</li>
  <li>Settings has an API tokens tab: a new token is shown once, and each one can be revoked.</li>
  <li>A forgotten-password reset revokes every token. Changing the password in Settings leaves them alone.</li>
</ul>

<h3>CORS</h3>

<p><code>CorsMiddleware</code> and <code>CorsConfig</code> are in <code>hydrakit/http</code>. The middleware answers preflights before routing, adds <code>Vary: Origin</code>, and never sends <code>Allow-Credentials</code>. <a href="/docs/routing.html#cors">Cross-origin requests</a> has the details.</p>
