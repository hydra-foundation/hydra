<p>The first of the security and operations work: what an operator needs to run the application rather than build it. Every log line now carries a request id and never a password. A fault can reach an error tracker. A load balancer has an endpoint to probe, and a deploy has a switch. The application key can now encrypt as well as sign, and it can be rotated without signing everyone out. Along the way, a stopped Redis turned out to take down the whole application, the health endpoint included, before anything could answer. That is fixed.</p>

<p>Everything here is new or optional, so this is a patch. One signature did change: <code>RedisStore</code>&rsquo;s constructor now takes <code>Redis|Closure</code> where it took <code>Redis</code>. Every argument it accepted before it still accepts, and PHP checks no constructor against its parent&rsquo;s, so no caller or subclass is affected. The release gate now recognises that shape, for constructors only.</p>

<h3>Upgrading</h3>

<p>Nothing is required. To take the new pieces, copy what the skeleton did: put <code>RequestIdMiddleware</code> first and <code>HealthMiddleware</code> second in <code>MIDDLEWARE</code>, and <code>MaintenanceMiddleware</code> right after <code>ErrorHandlerMiddleware</code>. Wrap the logger in <code>RedactingLogger</code> and <code>ContextualLogger</code>, and register <code>DownCommand</code> and <code>UpCommand</code> in <code>bin/console</code>. <code>hydrakit/core</code> now requires <code>ext-sodium</code>. It is bundled with most PHP builds, but a distribution that packages it separately, as Arch does with <code>php-sodium</code>, needs it installed. <a href="/docs/routing.html#operations">Health, maintenance and the log</a> has the details.</p>

<h3>Encrypter</h3>

<p><code>Encrypter</code> seals a string with XChaCha20&#8209;Poly1305 and gives back <code>v1.</code> followed by base64url. <code>decrypt()</code> returns the plaintext, or <code>null</code> for anything forged, truncated or sealed under a key that is no longer listed. The cipher key is derived from <code>APP_KEY</code> with HKDF, so the signer&rsquo;s HMAC key and the cipher key are never the same bytes. An optional context is bound in as associated data, so a value sealed for one column is refused in another. <code>SignerServiceProvider</code> binds it beside the <code>Signer</code>, and <code>FixedSignerServiceProvider</code> binds one under its published key. See <a href="/docs/install.html#encrypter">The encrypter</a>.</p>

<h3>Rotating the key</h3>

<p><code>APP_PREVIOUS_KEYS</code> lists retired keys, newest first, and both the signer and the encrypter still accept what those keys signed or sealed. <code>Signer</code> has always taken previous keys, but the provider never passed any, so until now rotating <code>APP_KEY</code> signed everyone out and revoked every link. See <a href="/docs/install.html#key">The application key</a>.</p>

<h3>The log</h3>

<p><code>RequestIdMiddleware</code> gives every request an id, sends it back as <code>X-Request-Id</code> and makes it available for the rest of the request. <code>ContextualLogger</code> adds it to every line, so every line one request wrote can be found together. The skeleton trusts the id nginx sets, which puts the same id in the access log. <code>RedactingLogger</code> blanks any context key naming a password, secret, token, authorization header, cookie, API key or CSRF token, at any depth. Matching ignores case, hyphens and underscores.</p>

<h3>Reporting</h3>

<p><code>ExceptionReporterInterface</code> is the hook for an error tracker, with <code>FakeExceptionReporter</code> to test against. When one is bound, the error handler reports every 5xx with the request id, method and path. The kernel reports what escapes the handler, the queue worker reports a job&rsquo;s final failure and the scheduler reports a task that threw. Each takes the reporter as an optional last constructor argument, and a reporter that fails is logged rather than allowed to replace the response. See <a href="/docs/routing.html#reporting">Reporting</a>.</p>

<h3>/up</h3>

<p><code>HealthMiddleware</code> answers <code>GET</code> and <code>HEAD /up</code> by running every <code>HealthCheckInterface</code> it was given. It answers 200 with each check named <code>ok</code>, or 503 naming the ones that are <code>down</code>, and the reason goes to the log rather than the body. <code>DatabaseHealthCheck</code> runs a <code>SELECT 1</code>; <code>CacheHealthCheck</code> writes, reads and deletes a key. <code>FakeHealthCheck</code> can pass, fail and change its answer between calls.</p>

<h3>Maintenance mode</h3>

<p><code>php bin/console down --message="…" --retry=600</code> writes a flag, and from then on every request gets a 503 with that message and <code>Retry-After</code>, rendered in whatever format the request asked for. <code>up</code> removes the flag. <code>/up</code> keeps answering throughout, and so do the scheduler and the queue. There is no bypass. The middleware renders the 503 itself rather than raising it, so a deploy is neither logged nor reported as a fault once per request.</p>

<h3>A Redis outage</h3>

<p><code>RedisStore</code> used to connect when it was built, and the pipeline builds every middleware up front. With Redis stopped, every request threw before the error handler or <code>/up</code> could answer. The store is now given an opener and connects on its first command. A failed connect is remembered for the rest of the request, so it costs one timeout rather than one per caller. <code>RedisConnection</code> also silences <code>connect()</code>&rsquo;s PHP warning. That warning duplicated the exception and, with errors displayed, sent headers early, so a 503 went out as a 200. With Redis stopped, <code>/up</code> now answers 503 naming <code>cache</code>, and a page that needs the store gets a rendered 500.</p>

<h3>In the skeleton</h3>

<p>All of the above, wired in. nginx passes its <code>$request_id</code> through, <code>/up</code> checks the database and the cache, the maintenance flag lives in <code>bootstrap/cache</code>, <code>.env.example</code> lists <code>APP_PREVIOUS_KEYS</code>, and <code>AppServiceProvider</code> passes a bound reporter to the error handler and the worker. Integration tests cover the <code>down</code>/<code>up</code> flow.</p>
