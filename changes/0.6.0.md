<p>Two pieces of work that do not resemble each other: validation grew from seven rules to thirty-three, and the admin gained dashboards, filter links and a reader&rsquo;s timezone. This is a minor rather than a patch because <code>RuleInterface</code> changed shape, and <code>^0.5</code> will not accept it &mdash; a consumer moves to <code>^0.6</code> deliberately, which is the point of the boundary.</p>

<h3>Upgrading from 0.5.8</h3>

<p>Four signatures moved. Three of them only matter if your application calls them directly, and the first one matters to anyone who wrote a rule.</p>

<dl class="defs">
  <dt><code>RuleInterface::validate()</code> takes a second parameter</dt>
  <dd>Every custom rule needs <code>Context $context</code> added to its signature. The body need not change &mdash; a rule that does not read it simply ignores it. This is what lets <code>Confirmed</code>, <code>Same</code> and the conditional <code>Required*</code> rules see the field they compare against.</dd>

  <dt><code>Input::rulesFor($value)</code> is now <code>Input::ruleSet()</code></dt>
  <dd>And <code>FormScreen::rulesFor($values)</code> is now <code>FormScreen::rules()</code>. Neither needs the submission any more, because an optional control leads with <code>Nullable</code> instead of having its rules withheld. <code>AdminController</code> is the only caller in the framework.</dd>

  <dt><code>Blueprint::__construct()</code> gained <code>$links</code></dt>
  <dd>Between <code>$screens</code> and <code>$perPage</code>. A blueprint is built by <code>Definition::compile()</code>, so a module written the documented way is unaffected.</dd>

  <dt><code>Renderer::screen()</code> takes a list of out-of-band templates</dt>
  <dd><code>$oob</code> is now <code>string|array|null</code>. A single template name still works.</dd>
</dl>

<p><code>hydrakit/database</code> now requires <code>hydrakit/validation</code>, which Composer resolves on its own. Validation itself still has no dependencies.</p>

<h3>Validation that can carry a signup form</h3>

<p>Seven rules validated a flat form and nothing else: no email, no date, no way to say a field was optional, and no way for a rule to see any value but its own. There are thirty-three now, and the validator work underneath them is the larger half.</p>

<p>A rule key is a dot path, and <code>*</code> walks a list. Each error is keyed to the concrete path that failed, and <code>validated()</code> comes back nested the way the input arrived.</p>

<div class="code">
  <div class="code-bar">php<button class="copy">copy</button></div>

<pre><code><span class="c-v">$result</span> = <span class="c-v">$this</span>-&gt;validator-&gt;<span class="c-f">validate</span>(<span class="c-v">$input</span>, [
    <span class="c-s">'email'</span>       =&gt; [<span class="c-k">new</span> <span class="c-t">Required</span>, <span class="c-k">new</span> <span class="c-t">Email</span>, <span class="c-k">new</span> <span class="c-t">Unique</span>(<span class="c-v">$this</span>-&gt;db, <span class="c-s">'users'</span>, <span class="c-s">'email'</span>)],
    <span class="c-s">'password'</span>    =&gt; [<span class="c-k">new</span> <span class="c-t">Required</span>, <span class="c-k">new</span> <span class="c-t">MinLength</span>(<span class="c-n">12</span>), <span class="c-k">new</span> <span class="c-t">Confirmed</span>],
    <span class="c-s">'bio'</span>         =&gt; [<span class="c-k">new</span> <span class="c-t">Nullable</span>, <span class="c-k">new</span> <span class="c-t">MaxLength</span>(<span class="c-n">500</span>)],
    <span class="c-s">'items'</span>       =&gt; [<span class="c-k">new</span> <span class="c-t">ArrayValue</span>, <span class="c-k">new</span> <span class="c-t">CountRange</span>(<span class="c-n">1</span>, <span class="c-n">20</span>)],
    <span class="c-s">'items.*.qty'</span> =&gt; [<span class="c-k">new</span> <span class="c-t">Required</span>(<span class="c-s">'How many?'</span>), <span class="c-k">new</span> <span class="c-t">Range</span>(<span class="c-n">1</span>, <span class="c-n">99</span>)],
]);

<span class="c-v">$result</span>-&gt;<span class="c-f">errors</span>();   <span class="c-cm">// ['items.1.qty' =&gt; 'How many?']</span></code></pre>
</div>

<dl class="defs">
  <dt>Presence</dt>
  <dd><code>Nullable</code>, <code>Sometimes</code>, <code>RequiredWith</code>, <code>RequiredWithout</code>, <code>RequiredIf</code>, <code>Accepted</code>.</dd>

  <dt>Type and size</dt>
  <dd><code>Text</code>, <code>Integer</code>, <code>Numeric</code>, <code>Boolean</code>, <code>ArrayValue</code>, <code>NumericRange</code>, <code>CountRange</code>.</dd>

  <dt>Format</dt>
  <dd><code>Email</code>, <code>Url</code>, <code>IpAddress</code>, <code>Uuid</code>, <code>Slug</code>, <code>Alpha</code>, <code>AlphaNumeric</code>, <code>Json</code>.</dd>

  <dt>Dates and comparison</dt>
  <dd><code>Date</code>, <code>DateRange</code>, <code>Confirmed</code>, <code>Same</code>, <code>Different</code>, <code>NotInList</code>, and <code>Callback</code> for a condition that wants no class of its own.</dd>

  <dt>Against the database</dt>
  <dd><code>Exists</code> and <code>Unique</code>, in <code>Hydra\Database\Validation</code> rather than with the validator, because that is where the connection is. Both refuse a table or column name that is not a bare identifier, since neither can travel as a bound parameter.</dd>
</dl>

<p>&ldquo;Optional&rdquo; is finally expressible. <code>ShortCircuitInterface</code> lets a rule end its field&rsquo;s chain without failing it, which is what <code>Nullable</code> and <code>Sometimes</code> do &mdash; so <code>[new Nullable, new MinLength(12)]</code> means &ldquo;if you are changing it, make it long enough&rdquo; rather than &ldquo;you must change it&rdquo;. The admin had written that rule by hand inside <code>Input</code>; it now uses the framework&rsquo;s.</p>

<p>Two of the new rules are deliberately stricter than PHP. <code>Url</code> takes a scheme allowlist defaulting to <code>http</code> and <code>https</code>, because PHP&rsquo;s own URL filter accepts <code>javascript:</code> and <code>data:</code> and a stored link is rendered into an <code>href</code> later. <code>Date</code> round-trips through its format, so <code>2026-02-31</code> fails rather than being read as the 3rd of March.</p>

<h3>Dashboards</h3>

<p>A dashboard is a module with no source and no fields: a <code>DashboardScreen</code> holding cards, each naming the template it fills and the presenter that fills it. The grid itself runs no queries &mdash; it renders placeholders and returns, and every card then fetches its own body from its own URL, so a slow count holds up one card and nothing else.</p>

<div class="code">
  <div class="code-bar">php<button class="copy">copy</button></div>

<pre><code><span class="c-t">DashboardScreen</span>::<span class="c-f">make</span>()-&gt;<span class="c-f">named</span>(<span class="c-s">'overview'</span>)-&gt;<span class="c-f">widgets</span>(
    <span class="c-t">Widget</span>::<span class="c-f">make</span>(<span class="c-s">'newest'</span>, <span class="c-s">'admin/widgets/newest'</span>)
        -&gt;<span class="c-f">titled</span>(<span class="c-s">'Newest accounts'</span>)
        -&gt;<span class="c-f">spanning</span>(<span class="c-n">6</span>)
        -&gt;<span class="c-f">reserving</span>(<span class="c-t">NewestAccountsWidget</span>::ACCOUNTS)
        -&gt;<span class="c-f">shaped</span>(<span class="c-t">Shape</span>::Rows)
        -&gt;<span class="c-f">from</span>(<span class="c-t">NewestAccountsWidget</span>::class),
)</code></pre>
</div>

<p><code>reserving()</code> and <code>shaped()</code> are one declaration in two halves &mdash; how many items the card is about to hold, and what one of them looks like &mdash; so the grid does not settle under the reader once per card as they land. <code>Shape</code> has four: <code>Rows</code>, <code>Bars</code>, <code>Block</code> and <code>Lines</code>.</p>

<h3>One time scope</h3>

<p>A card declared <code>periodic()</code> answers for the stretch of time the dashboard is set to, and its presenter implements <code>PeriodAwareInterface</code>. <code>Period</code> offers today, yesterday, the last 7, 30 and 365 days, and all time; the window is resolved once per request and handed to every card, so two widgets on one page cannot disagree about when now was.</p>

<p><code>Window::condition($column)</code> hands back the SQL and the values to bind, which is also how a widget avoids the one place a module meets the dialect: a rolling window is resolved in PHP and bound, never written as <code>NOW() - INTERVAL</code> or <code>datetime('now', &hellip;)</code>.</p>

<p>The control renders in the screen&rsquo;s toolbar rather than in the grid it replaces. A select inside its own swap target is destroyed by the answer it asked for, and htmx&nbsp;4 restores no focus after a swap &mdash; in a browser that fires <code>change</code> while arrowing through a closed select, the control was being torn out from under each keystroke. The toolbar is one masthead row: the summary strip at one end, the dates the cards cover, the period select and the page&rsquo;s refresh at the other.</p>

<p><code>summarised()</code> puts one card above the grid, on a band rather than in a box. Whether it follows the period is worth deciding rather than defaulting: a strip answering for all time above a grid that narrows puts two questions in one typeface and reads as one number disagreeing with itself.</p>

<h3>The reader&rsquo;s timezone</h3>

<p>Everything is stored in UTC and read by people who are not. <code>TimezoneInterface</code> is the seam &mdash; one method, <code>zone()</code>, answered per request &mdash; and binding nothing gives you <code>FixedTimezone</code> at UTC, which is what the rows already hold.</p>

<p>Bind one and <code>Field::datetime()</code> renders in it, and <code>Period::Today</code> and <code>Period::Yesterday</code> start at its midnight. That second one is the bug worth naming: a dashboard taking midnight from UTC drops the evening&rsquo;s rows the moment UTC rolls over, hours before the day has ended for the person looking at it, and the screen says nothing. An export is passed no zone and keeps the stored instant.</p>

<h3>Filter links</h3>

<p>A bar of named views above a list, each a preset over filters the source already answers, so no source knows links exist.</p>

<div class="code">
  <div class="code-bar">php<button class="copy">copy</button></div>

<pre><code>-&gt;<span class="c-f">links</span>(
    <span class="c-t">Link</span>::<span class="c-f">make</span>(<span class="c-s">'All'</span>),
    <span class="c-t">Link</span>::<span class="c-f">make</span>(<span class="c-s">'Open'</span>)-&gt;<span class="c-f">where</span>(<span class="c-s">'status'</span>, <span class="c-s">'open'</span>),
    <span class="c-t">Link</span>::<span class="c-f">make</span>(<span class="c-s">'Closed'</span>)-&gt;<span class="c-f">where</span>(<span class="c-s">'status'</span>, <span class="c-s">'closed'</span>),
)</code></pre>
</div>

<p>Declaring them routes <code>GET {module}/counts</code> for the tallies, which arrive on a request of their own so the bar is clickable before they land. Each is counted the way clicking that link would be read, so the number beside a link and the table it leads to cannot disagree. The column has to be one the <em>source</em> lists as filterable; <code>admin:check</code> verifies the pairing, and this is the direction that otherwise fails silently.</p>

<h3>Leaving a row keeps the view you left</h3>

<p>Opening a row threw away the view the visitor had narrowed the table to: Back, Cancel and the list a save returned to all landed on the module&rsquo;s defaults. List state lives in the query string, so the fix is to carry it &mdash; a list draws View, Edit, Delete and New with its own criteria on them, and the row screen hands those to its Back and its Cancel.</p>

<p><code>Criteria::queryString()</code> returns nothing when the state matches the module&rsquo;s defaults, so a list nobody has narrowed leaves its row URLs bare, and what it does return is byte-for-byte the URL the filter link pushed. A form&rsquo;s <code>action</code> carries it too, which is what lets a save without htmx find the list it was made from.</p>
