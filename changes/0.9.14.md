<p>Until now, what the scheduler did was gone as soon as it did it: <code>schedule:run</code> printed a table and dropped it. Each run is now recorded, and the skeleton&rsquo;s admin shows what is scheduled, when it runs next, whether it is running now, and every run of the last week.</p>

<p>Everything here is new, so this is a patch.</p>

<h3>Upgrading</h3>

<p><code>hydrakit/scheduler</code> now requires <code>hydrakit/database</code>, for <code>DatabaseRunLog</code>. Nothing is recorded unless the application binds a run log; the default keeps nothing.</p>

<p>To get the two screens in an application built on the skeleton, run the new migration (it creates <code>scheduled_runs</code>), bind <code>RunLogInterface</code> to <code>DatabaseRunLog</code> and schedule <code>PruneScheduledRuns</code> in <code>AppServiceProvider</code>, then copy <code>ScheduleSource</code>, <code>ScheduledRunsSource</code>, <code>SchedulerModule</code> and <code>ScheduledRunsModule</code> from <code>src/Admin</code> and register the modules.</p>

<h3>The scheduler</h3>

<ul>
  <li><code>TaskRun</code> gains <code>startedAt</code>, <code>durationMs</code> and <code>error</code>, the exception&rsquo;s class and message on one line. All three are optional.</li>
  <li><code>Runner</code> hands every run to a <code>RunLogInterface</code>. A run log that throws is logged as a warning, and the tick carries on.</li>
  <li><code>DatabaseRunLog</code> records runs in <code>scheduled_runs</code>, gives the newest per task with <code>latest()</code>, and deletes old ones with <code>prune()</code>. <code>PruneScheduledRuns</code> prunes to <code>SCHEDULE_KEEP_DAYS</code>, 7 by default.</li>
  <li><code>CronExpression::next()</code> returns the next minute an expression matches, in the time&rsquo;s own zone, or null if it never does within five years.</li>
  <li><code>LockDirectory::isHeld()</code> says whether a task is running, without taking or creating its lock.</li>
</ul>

<h3>The admin</h3>

<ul>
  <li>Monitoring &rarr; Scheduler lists each task with its kind, cron, next due time, whether it is running, and its last run, outcome and duration. A task opens on its last error.</li>
  <li>Monitoring &rarr; Runs lists every run, newest first, filtered by task, by outcome, or to leave out the runs that handled nothing. A task links to its runs, and a run back to its task.</li>
</ul>
