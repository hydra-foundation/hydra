<p>Until now, the application&rsquo;s log went to stderr and nowhere a browser could reach. The skeleton now writes it to a file as well, and Monitoring &rarr; Logs reads the end of that file, newest first. A line and the request that wrote it link to each other, across Logs and Activity.</p>

<p>Everything here is new, so this is a patch. One change in behaviour, and one in the skeleton&rsquo;s defaults, are covered under Upgrading.</p>

<h3>Upgrading</h3>

<p>A <code>-&gt;filterable()</code> field with no options now renders as a text box. It used to render as a select holding only &ldquo;All&rdquo;, which filtered nothing.</p>

<p>The skeleton&rsquo;s <code>LOG_PATH</code> now defaults to <code>storage/logs/hydra.log</code> instead of <code>php://stderr</code>, and <code>LOG_STDERR=true</code> keeps every line in <code>docker logs</code> too. PHP&#8209;FPM and the scheduler write the file as different users, so run <code>chmod 1777 storage/logs</code> once outside <code>./bin/dev</code>. Without it, web requests fall back to stderr alone, without a warning.</p>

<p>To get the Logs screen in an application built on the skeleton, run the new migration (it adds <code>activity.request_id</code>), then copy <code>src/Config/LogConfig.php</code>, the logger binding in <code>AppServiceProvider</code>, <code>src/Admin/Sources/LogSource.php</code> and <code>src/Admin/Modules/LogsModule.php</code>, and register the module. <code>RecordActivityMiddleware</code>, <code>ActivitySource</code> and <code>ActivityModule</code> each gain the request id.</p>

<h3>The log</h3>

<p><code>LogReader</code> parses a <code>StreamLogger</code> file back into <code>LogRecord</code>s: the time, the level, the message, an exception&rsquo;s trace, the context and the request id. <code>latest($maxBytes)</code> reads the end of the file, and <code>at($offset)</code> finds one record again by where it starts. A record the window cuts into is left out, not read from its middle. <code>FanOutLogger</code> writes one record to several loggers, and a logger that throws does not stop the rest.</p>

<h3>The admin</h3>

<p><code>Page</code> takes a <code>note</code>, shown beside the list&rsquo;s count. In the skeleton:</p>
<ul>
  <li>Monitoring &rarr; Logs lists the last 2&nbsp;MB of the log (<code>LOG_READ_BYTES</code>), filtered by level or request id, and searched by message. A line opens on its trace and its context.</li>
  <li>Each Activity row stores its request id. Activity&rsquo;s Show links to that request&rsquo;s log lines, and each log line links back.</li>
</ul>
