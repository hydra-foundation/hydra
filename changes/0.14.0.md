This finishes the Access module. Beside the API tokens it gained in 0.12.0, the skeleton's Access now has a Sessions tab: every browser signed in to every account, where from and since when, each one revocable, built on the sign-in records 0.13.0 added. **Sign out everywhere** ends every sign-in and API token of one user in a single action, from Users or from Sessions. The admin gains `Definition::tabLabel()`, so the strip can read `API tokens | Sessions` under an entry still called Access.

Nothing is removed or renamed: `Blueprint` takes the new label as its last argument, with a default. This is 0.14.0 rather than a patch because the skeleton depends on the new method; widen your constraint to `^0.14` to take it.

## Upgrading

- **The skeleton:** Copy `SessionsModule`, `SessionSource`, `Auth/SignInWindow.php`, `Auth/SignOutEverywhere.php` and the two `SignOut…Everywhere` actions. Register `SessionsModule` after `AccessModule`, add `->tabLabel('API tokens')` to `AccessModule` and the `sign-out-everywhere` row action to `UsersModule`, and add `'sessions' => ['owner', 'ip']` to `AuditAdminEventsListener::AUDITED`. `PruneSignIns` now takes a `SignInWindow` in place of a clock.

## The skeleton

- Administration → Access gains a Sessions tab, and its strip reads `API tokens | Sessions`. Sessions lists every live sign-in: owner, IP address, browser, when it began and when it was last seen, searchable by username, email or address, with your own marked "This is you". Revoking a sign-in signs that browser out on its next request; your own can't be revoked from here, since Sign out does that. **Sign out everywhere**, on a user's row under Users and on each of their sign-ins, ends every sign-in and API token they have at once, and says how many. On your own account it keeps the sign-in you're using. Both are audited.

## The admin

- `Definition::tabLabel()` names a module in the strip of tabs when its title shouldn't. A parent named after its family keeps that name on its sidebar entry, heading and breadcrumb, and says which list it is in the strip: the skeleton's Access reads `API tokens | Sessions`. `Blueprint` takes it as its last argument, defaulting to null.
