<p>A fresh checkout could not run <code>bin/console key:generate</code>, because listing the commands built every one of them and one of those needed <code>APP_KEY</code>. That is fixed in the framework. The rest of the release is the skeleton&rsquo;s: a group of hardening fixes to sign-in, passwords, API tokens and the admin.</p>

<p>Nothing is removed from the framework, so this is a patch.</p>

<h3>Upgrading</h3>

<p>An application built on the skeleton gets the fixes by copying them from the <a href="https://github.com/hydra-foundation/app/compare/v0.9.14...v0.9.15">skeleton diff</a>. The ones that change behaviour:</p>

<ul>
  <li>Minting an API token in Settings now asks for the current password.</li>
  <li>Changing a password in Settings or under Users now revokes the user&rsquo;s API tokens, as the emailed reset already did.</li>
  <li>After ten sign-in attempts for one username in fifteen minutes, the login form answers <code>429</code> for that name, whichever client the attempts came from. The emailed reset is not affected.</li>
  <li><code>App\Authorization\ManageUser</code> is gone. Nothing checked it.</li>
</ul>

<h3>The console</h3>

<ul>
  <li><code>ConsoleApplication::addLazy()</code> wraps each factory in Symfony&rsquo;s <code>LazyCommand</code>, so <code>list</code> and <code>has()</code> read the name and description off <code>#[AsCommand]</code> without building the command.</li>
  <li>In the skeleton&rsquo;s <code>bin/console</code>, the route cache, maintenance and admin commands move from <code>add()</code> to <code>addLazy()</code>. Only commands that resolve nothing from the container are added eagerly now.</li>
</ul>

<h3>The skeleton</h3>

<ul>
  <li>The login form keeps a budget per username on top of the one per client. It is counted before the password is checked and keyed on the name as typed, so an unknown name is refused the same way as a real one.</li>
  <li>The email-change form checks the password before saying an address is taken, so it can no longer be used to find out which addresses have accounts.</li>
  <li>An admin cannot change their own role. A last admin demoting themselves would leave nobody who could undo it, which is why deleting yourself was already refused.</li>
  <li>The dashboard&rsquo;s cards and System Health are behind <code>AccessAdmin</code>, like the activity, users and audit modules they read from.</li>
  <li>Anonymous visitors are no longer told the PHP, nginx and Hydra versions: <code>expose_php=Off</code>, <code>server_tokens off</code>, and no version on the sign-in page. The admin footer still shows it.</li>
  <li>The Composer image is pinned to <code>composer:2</code> rather than <code>:latest</code>.</li>
</ul>
