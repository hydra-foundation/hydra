Two fixes found on williamhleucka.com once a dark theme was picked in the admin. The bell's menu stayed white under every palette, and the site's public pages took on the signed-in admin's theme. Each page now wears the palette that belongs to it.

It is a patch: nothing a package exports changed. The admin fix is a stylesheet rule, and the layout change lives in the skeleton, which an application copies once rather than takes from Composer.

## Upgrading

- **The skeleton:** An app made from the skeleton merges the change to `views/layouts/base.php` (the `data-theme` default) and `views/layouts/admin.php` (the `theme` section). A layout of its own that should wear the admin's palette starts the same section.

## The admin

- The notifications menu under the bell takes the theme in force. Bootstrap 5.2 writes the dropdown's colours as literals, so the menu was white under every palette, dark ones included; the admin stylesheet now maps them to the theme's tokens for any dropdown in the admin.

## The skeleton

- The public pages keep the site's palette when an admin is signed in. The theme picked under Settings is the admin's appearance, but the shared layout painted every page in it, the home page included. `layouts/base.php` now defaults to the fallback palette and `layouts/admin.php` names the signed-in person's.
