<p>A test client, a clock, and a harness for the skeleton. Every change to an existing signature appends an optional parameter, which a caller that never passes it cannot tell happened, so nothing that compiled against 0.5.7 stops compiling &mdash; that is why this is a patch. It does add a dependency, <code>psr/clock</code>, which Composer installs on its own.</p>

<h3>An HTTP client for tests</h3>

<p>Until now every integration flow built its own <code>ServerRequest</code>, set the peer address, minted a CSRF token into the session and wrapped the answer in assertions of its own &mdash; the framework&rsquo;s six flows and the skeleton&rsquo;s three each had a copy. <code>Hydra\Http\Testing\Client</code> is that code once. It sends a request through the application&rsquo;s real pipeline, in process: routing, middleware, sessions, CSRF and the error renderer all run, and nothing listens on a port.</p>

<div class="code">
  <div class="code-bar">php<button class="copy">copy</button></div>

<pre><code><span class="c-v">$http</span> = <span class="c-t">Client</span>::<span class="c-f">for</span>(<span class="c-v">$container</span>, [<span class="c-t">CarriesCsrfToken</span>::<span class="c-f">for</span>(<span class="c-v">$container</span>)]);

<span class="c-v">$http</span>-&gt;<span class="c-f">post</span>(<span class="c-s">'/login'</span>, [<span class="c-s">'username'</span> =&gt; <span class="c-s">'boss'</span>, <span class="c-s">'password'</span> =&gt; <span class="c-v">$password</span>])
    -&gt;<span class="c-f">assertRedirect</span>(<span class="c-s">'/admin'</span>);

<span class="c-v">$http</span>-&gt;<span class="c-f">htmx</span>(<span class="c-s">'div#admin-body'</span>)-&gt;<span class="c-f">get</span>(<span class="c-s">'/admin/users?q=clerk'</span>)
    -&gt;<span class="c-f">assertOk</span>()
    -&gt;<span class="c-f">assertFragment</span>()
    -&gt;<span class="c-f">assertSee</span>(<span class="c-s">'&gt;clerk&lt;/td&gt;'</span>);</code></pre>
</div>

<dl class="defs">
  <dt>Requests</dt>
  <dd><code>get</code>, <code>post</code>, <code>put</code>, <code>patch</code> and <code>delete</code>. A POST arrives parsed, as PHP would parse it; the other methods arrive as raw bytes only, so an application that forgot to parse a PUT fails in the test the way it would in production.</dd>

  <dt>Modifiers</dt>
  <dd><code>htmx($target)</code>, <code>withHeader()</code>, <code>from($peer)</code>, <code>followingRedirects($limit)</code> and <code>unprepared()</code>. Each returns a new client and leaves the one it was called on alone.</dd>

  <dt>Redirects</dt>
  <dd>Not followed unless asked. When they are, a 302 or 303 becomes a GET without the body, a 307 or 308 repeats both, an htmx redirect directive is followed as a full page, and a loop fails naming every hop.</dd>

  <dt>Preparers</dt>
  <dd>A <code>RequestPreparer</code> touches every request before it is sent. <code>Hydra\Csrf\Testing\CarriesCsrfToken</code> is the one that ships: it adds the session&rsquo;s token to unsafe requests and leaves alone one that already carries a token, so a test can still send a stale one on purpose. <code>send()</code> skips all of it and dispatches a request exactly as built.</dd>
</dl>

<p>Every call answers with a <code>TestResponse</code>, whose assertions chain and whose failures print the status, the <code>Location</code> and the text of the body rather than a wall of markup: <code>assertStatus</code>, <code>assertOk</code>, <code>assertRedirect</code>, <code>assertHeader</code>, <code>assertHeaderMissing</code>, <code>assertSee</code>, <code>assertDontSee</code>, <code>assertSeeInOrder</code>, <code>assertHtmxRedirect</code> and <code>assertFragment</code>. <code>directive()</code> reads the DOM markers htmx&nbsp;4 is signalled with, since it reads no response headers.</p>

<h3>A clock, on PSR&#8209;20</h3>

<p>Anything that asked for the time asked PHP directly, so a test of it was a test of whatever day the suite ran on &mdash; the admin export tests failed if they ran across midnight. <code>Psr\Clock\ClockInterface</code> is now bound by <code>ClockServiceProvider</code>, which <code>Kernel::application()</code> registers, to a <code>SystemClock</code>. The mail <code>Date</code> header and the date in an export&rsquo;s filename read it.</p>

<p><code>Hydra\Core\Testing\FrozenClock</code> is the double: it starts at a fixed instant, and <code>set()</code> and <code>advance('+1 day')</code> move it. An interval it cannot read throws naming it, rather than leaving the clock where it was.</p>

<h3>A harness for the skeleton</h3>

<p>The skeleton&rsquo;s flow tests each booted the provider stack by hand, and two of them had left out the event dispatcher &mdash; so the admin events in those flows fired into nothing and the tests passed anyway. <code>tests/Support/TestApp.php</code> boots the providers <code>Bootstrap</code> does, in the same order, with the session, cache, signer, mailer and database swapped for their doubles. <code>TestAppTest</code> fails when <code>Bootstrap</code> gains a provider the harness has not.</p>

<div class="code">
  <div class="code-bar">php<button class="copy">copy</button></div>

<pre><code><span class="c-v">$app</span> = <span class="c-t">TestApp</span>::<span class="c-f">boot</span>();
<span class="c-v">$app</span>-&gt;<span class="c-f">seed</span>(<span class="c-s">'boss'</span>, <span class="c-t">Role</span>::<span class="c-t">Admin</span>);
<span class="c-v">$app</span>-&gt;<span class="c-f">login</span>(<span class="c-s">'boss'</span>)-&gt;<span class="c-f">assertStatus</span>(<span class="c-n">302</span>);
<span class="c-v">$app</span>-&gt;<span class="c-f">http</span>()-&gt;<span class="c-f">get</span>(<span class="c-s">'/admin/audit'</span>)-&gt;<span class="c-f">assertOk</span>();</code></pre>
</div>

<p><code>TestHttpProvider</code> and <code>TestAdminProvider</code> are gone with it; <code>TestApp</code> is the one list. They lived in the skeleton&rsquo;s <code>tests/</code>, not in a package, so an application made from an earlier skeleton keeps its own copies.</p>
