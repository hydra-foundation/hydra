<p>A new package and two new generators. Nothing that existed changed shape: a package is a set of symbols that did not exist before, and <code>make:module</code> gained an option rather than changing a default. That makes it a patch &mdash; the rule is what a release <em>removes or narrows</em>, not how much it adds. The mail package brings 71 tests at 99% line coverage; the skeleton gains 15 for the generators.</p>

<h3><code>hydrakit/mail</code></h3>

<p>The next things the roadmap wants &mdash; password reset, email verification, notifications &mdash; all end in sending an email, and until now there was nothing to send it with. <a href="/docs/mail.html">Mail</a> is one contract, <code>MailerInterface</code>, over three transports: <code>smtp</code>, which delivers; <code>log</code>, which writes the message to the application log; and <code>array</code>, which keeps it in memory.</p>

<p>The skeleton registers the provider and its <code>.env.example</code> sets <code>log</code>, so a fresh checkout never mails anyone. Configured for SMTP, the transport holds to a few rules that are easy to get quietly wrong:</p>

<dl class="defs">
  <dt>Every recipient is accepted, or the message is not sent</dt>
  <dd>A send that reaches some recipients and then throws cannot be retried without mailing the others twice.</dd>

  <dt><code>tls</code> means TLS</dt>
  <dd>A server that does not offer STARTTLS is an error, not a plain&#8209;text fallback. The certificate is verified, and nothing older than TLS&nbsp;1.2 is accepted.</dd>

  <dt>Errors name the step, never the line sent</dt>
  <dd>So a refused login reports <em>the credentials</em> and the server&rsquo;s reply, and the password cannot end up in a log.</dd>

  <dt>Bad settings fail where they were set</dt>
  <dd>An unknown transport, a port out of range, SMTP without a host, or credentials with <code>MAIL_ENCRYPTION=none</code> each throw naming the setting.</dd>
</dl>

<p><code>Hydra\Mail\Testing\FakeMailer</code> ships with it, for the same reason the doubles in <a href="0.5.6.html">0.5.6</a> did: registered after the real provider, it records what was sent and answers <code>assertSentTo()</code>, <code>assertSent()</code>, <code>assertNotSent()</code> and <code>assertNothingSent()</code>.</p>

<div class="note warn">
  <span class="label">Not yet</span>
  <p>No attachments, no custom headers, no addresses outside ASCII, and no queue &mdash; a send happens inside the request that asked for it, one connection per message.</p>
</div>

<h3><code>make:admin</code> and <code>make:source-test</code></h3>

<p><a href="0.5.5.html">0.5.5</a> shipped the generators one file at a time, which left a module five commands and a naming convention away. <code>make:admin invoice</code> writes the source, the module and the source&rsquo;s contract test from one table; <code>--writable</code> makes the source and its test writable, and <code>--repository</code> adds the entity and repository. It checks every file first and writes none of them if any exists, so a half&#8209;generated module is not a state it can leave behind.</p>

<p><code>make:source-test</code> is the piece that was missing. It writes the fixture the published contract case asks for &mdash; five rows, a search term that lands in a column the source searches, and the rows to create and edit when the source is writable &mdash; from the same reading of the table <code>make:source</code> makes, so the two cannot disagree. It also prints a first draft of the table&rsquo;s SQLite twin for <code>TestSchema.php</code>, because the test reads that, never the migrations.</p>

<h3>Also</h3>

<dl class="defs">
  <dt><code>make:module --source</code></dt>
  <dd>Names the source class instead of guessing it from the module&rsquo;s name. The guess made <code>AddresseSource</code> out of <code>addresses</code>; <code>make:admin</code> always passes it.</dd>
</dl>
