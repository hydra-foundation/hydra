The SSE hub had a ceiling nobody could see. It waited on every browser with `stream_select`, which cannot watch a descriptor numbered 1024 or higher, and the skeleton's prod limits let it get there: past about a thousand open tabs it stopped serving and logged nothing. On PHP 8.6 it now waits through the new `Io\Poll` API, which has no such ceiling; below 8.6 the ceiling is a number the hub enforces and says out loud. The skeleton moves to PHP 8.6 alongside, and its nginx stops serving 502s after a rebuild.

A minor, not a patch: an app on PHP 8.4 or 8.5 with `SSE_MAX_CONNECTIONS` set above 896 now has a hub that refuses to start until the setting is lowered, and `SseServeCommand`'s constructor changed.

## Upgrading

- **Broadcast:** On PHP 8.4 or 8.5 with `SSE_MAX_CONNECTIONS` set above 896 (the skeleton's `.env.example` had `1000`), `sse:serve` refuses to start. Remove the line to take the default, set 896 or less, or run the hub on PHP 8.6. Code that built `SseServeCommand` itself, rather than through `BroadcastServiceProvider`, now passes it the `HubFactory` and a logger. `HubConfig::$maxConnections` is `?int`: null means unset, and `HubConfig::for($poller)` settles it (the hub does this itself).
- **The skeleton:** An app that moves its own `docker/php/Dockerfile` to `FROM php:8.6-fpm` takes three more changes from the skeleton's, or the build fails. Opcache is part of PHP since 8.5, so it leaves `docker-php-ext-install` (the skeleton's line asks PHP first, and works on 8.4 too). `pecl` is gone from the 8.6 images, so extensions install through PIE (`COPY --from=ghcr.io/php/pie:1-bin /pie /usr/bin/pie`, then `pie install`), which needs `libtool` in the apt list. And phpredis and Xdebug need `^6.4@RC` and `^3.6@alpha`: their stable releases refuse 8.6 or fail to compile on it. Then `./bin/prod up -d --build`.
- **The skeleton:** Merge the `resolver` line and the `zone` and `resolve` changes to the `php-fpm` upstream into `docker/nginx/default.conf`, then `docker restart` the nginx container: a reload keeps the old file. `resolve` needs nginx 1.27.3 or newer, which `nginx:alpine` has.

## Broadcast

- The SSE hub waits through PHP 8.6's `Io\Poll` (epoll on Linux) where PHP has it, and through `stream_select` below 8.6. `stream_select` cannot watch a descriptor numbered 1024 or higher, and once any socket passed that the hub stopped serving without a word: no events, no heartbeats, nothing logged. The skeleton's prod limits reached it at the default cap. Now:

  - **On 8.6** there is no ceiling but the process's open-file limit.
  - **Below 8.6** an unset `SSE_MAX_CONNECTIONS` is 896, what `stream_select` can serve. An explicit value over that stops `sse:serve` at start, before it binds the port, with the fix in the message.
  - **If select hits the ceiling anyway**, the hub closes the newest stream each round until it can watch the rest, and says so in the log at most once a minute, instead of going quiet.
  - `sse:serve`'s start line names the poller and the cap (`listening on 0.0.0.0:8080 (epoll, up to 1000 streams)`), and the hub's status report carries the poller for System Health.

## The skeleton

- The Docker image is built on PHP 8.6. The packages still require 8.4 or newer, and `config.platform.php` stays at 8.4.0, so the lock still installs on 8.4. Two extensions are pre-releases until their 8.6 support ships stable: phpredis 6.4.0RC1 in every build and Xdebug 3.6.0alpha1 in dev builds. PCOV has no release that builds on 8.6 yet, so dev builds skip it; local coverage runs on Xdebug.
- nginx follows the php container to its new address when the container is recreated. It used to resolve `php` once at start and keep sending to the old address, so `up -d --build` after a Dockerfile or compose change left every page a 502 until nginx was restarted too. `docker/nginx/default.conf` now asks Docker's DNS again every 10 seconds (`resolver` plus `server php:9000 resolve` in the upstream), and keeps the upstream's keepalive pool.
