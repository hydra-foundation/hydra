<p>Recurring work used to mean a crontab line per job, kept on the server and out of version control. A new package, <code>hydrakit/scheduler</code>, reduces the crontab to one line, <code>schedule:run</code> every minute. What runs, and when, is declared in the application. It is the first half of the queue: a worker needs something to start it and to clean up after it. Nothing already published changed, so this is a patch.</p>

<h3>Upgrading</h3>

<p>Nothing is required. To use the scheduler, require <code>hydrakit/scheduler</code>, register <code>SchedulerServiceProvider</code> with a lock directory, add <code>ScheduleRunCommand</code> to the console, and add the cron entry. The skeleton does all four except the cron entry. <a href="/docs/scheduler.html">The scheduler</a> has the details.</p>

<h3>Declared in a provider, locked by the kernel</h3>

<p>A <code>Schedule</code> takes a class and a frequency: <code>run()</code> for a <code>TaskInterface</code> that works once, and <code>drain()</code> for a <code>BatchInterface</code> that is called until it reports nothing left or its <code>for()</code> budget runs out. Frequencies are <code>everyMinute()</code>, <code>hourly()</code>, <code>dailyAt()</code>, <code>weekly()</code> or a five&#8209;field <code>cron()</code>, read in <code>SCHEDULE_TIMEZONE</code> or else <code>APP_TIMEZONE</code>. Due tasks run one after another, in the order they were declared. Each one holds a <code>flock()</code> lock, so a run is never started beside one still going, and a crash cannot leave a lock behind. A lock held longer than <code>warnAfter()</code> logs a warning every minute instead of being broken. A task that throws is logged, the rest still run, and the command exits non&#8209;zero.</p>

<h3>In the skeleton</h3>

<p>The scheduler is registered, with its locks under <code>bootstrap/cache/scheduler</code>. The schedule is empty for now, and the queue will be the first thing on it. <code>docker-compose.yml</code> has a <code>scheduler</code> service that starts <code>schedule:run</code> at the top of every minute, so the development stack needs no crontab. In production it restarts unless stopped.</p>
