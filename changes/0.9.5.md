<p>The skeleton has always answered an error in the format the request asked for, with a renderer of its own that every application built on it had to copy. It is now in the framework, and it speaks one more format. A deliberate 429 on the dashboard, used to test it, found the other fix here: a card whose first load is refused never tries again. One new class and a template change, so this is a patch.</p>

<h3>Upgrading</h3>

<p>Nothing is required; the kernel still binds <code>PlainTextErrorRenderer</code>. To negotiate, bind <code>ErrorRendererInterface</code> to <code>new NegotiatingErrorRenderer($responder, '#app-error')</code>, naming the region of your layout that htmx errors should land in, and delete any copy of the skeleton&rsquo;s renderer. <strong>JSON errors change shape</strong> if you do: the skeleton&rsquo;s copy sent <code>{error, status}</code>, and the framework&rsquo;s sends problem details.</p>

<h3>NegotiatingErrorRenderer</h3>

<p>An htmx request gets an HTML fragment, sent out of band to the region you named or, with none, swapped where htmx would put it. A request that prefers JSON, including any <code>+json</code> type, gets RFC&nbsp;9457 problem details as <code>application/problem+json</code>: <code>type</code>, <code>title</code>, <code>status</code> and, when it says more than the title, <code>detail</code>. With debug on it adds the exception, message, file and line. A browser gets a page. A request naming neither, which is what curl and a health check send, still gets plain text. <code>Accept</code> is read by q-value, and a tie goes to the type listed first. Every answer carries <code>Vary: Accept, HX-Request</code>, because one URL now answers in several formats. <a href="/docs/routing.html#errors">Errors</a> has the details.</p>

<h3>A card that could not load</h3>

<p>A dashboard card only polls once it has data, so a card whose first fetch was refused kept its placeholder for good. It now says it could not load and offers a Retry button that fetches that card again. The summary strip does the same. A card that already has data keeps it through a failed poll, as before. See <a href="/docs/admin.html#refreshing">Refreshing</a>.</p>

<h3>In the skeleton</h3>

<p>The skeleton&rsquo;s own <code>NegotiatingErrorRenderer</code> and its test are gone, and <code>AppServiceProvider</code> binds the framework&rsquo;s with <code>#app-error</code>. An integration test holds that selector to the element the layout actually has.</p>
