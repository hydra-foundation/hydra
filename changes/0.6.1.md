<p>Everything here adds to the admin, and nothing is taken away, so it is a patch and <code>^0.6</code> picks it up with a plain <code>composer update</code>. It very nearly was not. Two signatures had moved on the way: <code>ShowViewModel</code> took its new <code>$now</code> in the middle of the constructor, and <code>Input::required()</code> widened its message to <code>?string</code>. The release script refused the tag over both. The first was a real break for a positional caller and now sits at the end of the list. The second broke nobody, since <code>Input</code> is final, but a gate that reads signatures as text cannot tell that, so the old signature is back. Putting two symbols back was cheaper than asking every application to edit its constraint for a break that did not exist.</p>

<h3>Upgrading from 0.6.0</h3>

<p>Nothing is required. One change is worth making: the admin&rsquo;s stylesheet and script are now served by the package, and a copy in your <code>public/</code> directory will not pick up the controls below. Point <code>views/layouts/admin.php</code> at the package and delete the copies:</p>

<p><code>hydrakit/admin</code> now requires <code>hydrakit/cache</code>, which Composer resolves on its own.</p>

<h3>Forms and lists</h3>

<ul>
  <li><code>Input::checkbox()</code> and <code>Input::radios()</code>, with <code>asSwitch()</code> for a toggle. <code>required()</code> on a checkbox means ticked: an unticked box arrives as <code>"0"</code>, which <code>Required</code> would pass, so it gets <code>Accepted</code> and the message &ldquo;This must be ticked.&rdquo;</li>
  <li><code>Field::boolean()</code>, <code>Field::number()</code> with <code>decimals()</code>, <code>grouped()</code> and <code>suffix()</code>, and <code>Field::date()</code>.</li>
  <li><code>relative()</code> on a datetime (&ldquo;an hour ago&rdquo;), and <code>truncate()</code> for long text. Both keep the full value in a title attribute. An export gets neither, because a file read next week must not say &ldquo;an hour ago&rdquo; about when it was written.</li>
  <li>A number column aligns as a whole column, header included.</li>
</ul>

<p>All of it is under <a href="admin.html#fields">Fields and surfaces</a>.</p>

<h3>The admin serves its own stylesheet</h3>

<p><code>admin.css</code> and <code>admin.js</code> used to be copied into each application and kept up to date by hand. They are served from <code>{prefix}/assets/stylesheet</code> and <code>{prefix}/assets/script</code> now, with an ETag and a <code>304</code> when it matches (see <a href="admin.html#assets">The stylesheet and the script</a>), and outside the admin&rsquo;s middleware so the sign-in screen is styled before anyone has signed in. The URLs have no extension on purpose: the stock nginx rule for <code>.css</code> and <code>.js</code> serves files directly and would return a 404 before PHP saw the request.</p>

<h3>Health cards</h3>

<p><code>UptimeWidget</code>, <code>CacheWidget</code> and <code>ResourcesWidget</code> are the cards a system dashboard is made of, with <code>admin/partials/widget-health</code> and <code>widget-gauges</code> to draw them. A probe that fails reports the failure on its card rather than throwing. The skeleton puts them on a new System Health dashboard beside a <code>DatabaseWidget</code> of its own. See <a href="admin.html#health">Health cards</a>.</p>

<h3>Fixes</h3>

<ul>
  <li><strong>A response can now replace a header PHP set.</strong> The emitter appended every header value, so <code>session_start()</code>&rsquo;s <code>Cache-Control: no-store</code> stuck to every response and <code>withHeader()</code> could not override it. The first value of a name now replaces, and later values append, so repeated <code>Set-Cookie</code> headers survive.</li>
  <li><code>Status::NotModified</code> (304) exists.</li>
  <li>The console tests no longer depend on the terminal width. They failed between 50 and 54 columns, which is where the 0.6.0 release happened to run.</li>
</ul>
