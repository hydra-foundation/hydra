<p>The limiter last. Four prerequisites came first, each one unsafe or meaningless without the one above it.</p>

<dl class="defs">
  <dt>Client identity &mdash; <code>TrustedProxies</code> and <code>ClientIpResolver</code></dt>
  <dd><code>X-Forwarded-For</code> is walked from the <em>right</em>, skipping trusted hops. The old leftmost read handed a caller its own identity: prepend a hop and every per-IP budget resets on demand. <code>TRUSTED_PROXIES</code> (comma-separated CIDRs) replaces the old boolean, and empty means no proxy, headers ignored, socket peer wins. nginx no longer trusts the Docker bridge &mdash; a published port makes every external caller arrive from the bridge gateway, so that range let any client set its own <code>REMOTE_ADDR</code>.</dd>

  <dt>A counter store &mdash; the new <code>hydrakit/cache</code> package</dt>
  <dd><code>StoreInterface</code> with an atomic <code>increment($key, $by, $ttl)</code>: the window opens on the first hit and is never re-armed, so a steady stream cannot hold a counter open past its limit. Redis does it in one Lua script. Redis and array implementations, both passing one contract test, and no silent fallback &mdash; a per-process counter would multiply every limit by the pool size.</dd>

  <dt>Edge bounds &mdash; bounded before metered</dt>
  <dd><code>Range</code> and <code>InList</code> rules joined the validator, login fields are capped, and oversized input is refused at 17&nbsp;ms instead of reaching bcrypt at 226&nbsp;ms. <code>Criteria::MAX_PAGE</code> caps the offset, <code>MAX_SEARCH</code> caps the term, and <code>searchPattern()</code> escapes <code>%</code> and <code>_</code> so a search cannot ask for a scan.</dd>

  <dt>Store hardening &mdash; the limiter fails open without it</dt>
  <dd>An error <em>reply</em> is no longer a count of zero: every command clears and reads the last error, and <code>increment()</code> and <code>ttl()</code> demand an int, so an out-of-memory, unauthenticated, wrong-type or read-only Redis raises instead of casting <code>false</code> to 0 and reading as &ldquo;under the limit&rdquo;. A read timeout is set, which phpredis leaves unlimited &mdash; the connect timeout only ever covered the handshake. Connect, auth and select are each checked for <code>false</code> rather than only for a thrown exception, since a half-opened Redis answers every command with an error. Production runs Redis <code>noeviction</code>: under <code>allkeys-lru</code> the counters were evictable, so memory pressure &mdash; or anyone able to create it &mdash; reset every budget. <code>flush()</code> is a SCAN over the store&rsquo;s own prefix, because <code>FLUSHDB</code> would take the sessions and every other tenant with it.</dd>
</dl>

<p>Then the limiter itself, as the new <code>hydrakit/throttle</code> package. A policy is a name, a count and a window; spending the last request refuses with a 429 carrying <code>Retry-After</code>. It follows the CSRF precedent rather than going into <code>http</code> or <code>cache</code>: it needs both, and neither of those should have to require the other. The global budget sits <em>inside</em> the error handler and ahead of the session, the body parser and the database, so a refusal costs nothing and an unreachable store renders as a 500 instead of escaping the pipeline. <code>POST /login</code> gets a tighter one &mdash; five attempts in ten minutes &mdash; through its own middleware class named in the route attribute, which is the pattern for a per-route budget, since the attribute names middleware by class and cannot carry arguments.</p>
