<p>0.7.1 put a fake behind every contract. This release audits every package against <a href="/docs/ethos.html#checking">the ethos page&rsquo;s six questions</a>. Only the second one, whether a thing can be faked without the real thing present, found much: the test suites were still writing the same doubles by hand, for interfaces Hydra depends on but had shipped no fake for. Everything here is a new class, a new method or a new optional parameter, so it is a patch.</p>

<h3>New fakes</h3>

<ul>
  <li><strong><code>Hydra\Event\Testing\FakeDispatcher</code></strong> keeps every event and delivers none: <code>assertDispatched()</code>, optionally with a closure to check the event, <code>assertNotDispatched()</code>, <code>assertNothingDispatched()</code> and <code>first()</code>. It replaces three recording dispatchers in admin and auth.</li>
  <li><strong><code>Hydra\Http\Testing\FakeHandler</code></strong> is the rest of the pipeline in a middleware test. <code>respondingWith($response)</code> or <code>throwing($e)</code>, plus <code>assertHandled()</code>, <code>assertNotHandled()</code> and <code>lastRequest()</code>. It replaces eighteen hand-written handlers across the framework and the skeleton. <a href="/docs/routing.html#middleware">Controllers and routes</a> has the detail.</li>
  <li><strong><code>Hydra\Auth\Testing\ArrayUserProvider</code></strong> and <strong><code>FakeHasher</code></strong>. The provider counts its lookups, which is how a test shows the guard caches the user for the request. The hasher costs nothing, passes the hasher contract case, and counts its operations, so the timing defence is checked by counting work instead of measuring time. <a href="/docs/auth.html#testing">Authentication</a> has the detail.</li>
  <li><strong><code>Hydra\Cache\Testing\FakeStore</code></strong> sits in front of a real store and fails on demand, with <code>failOn()</code> for keys containing a string and <code>failAll()</code> for a Redis that is down. It is the cache counterpart of 0.7.1&rsquo;s <code>FakeConnection</code>.</li>
</ul>

<h3>The clock, everywhere it was read directly</h3>

<p><code>FrozenClock</code> has been in <code>core</code> since 0.5.8, but three places still read the wall clock. <code>ArrayStore::withClock()</code> now takes a PSR clock. The constructor still takes a closure; widening its type would have been compatible, but the release gate counts any changed type as a break, so the clock came in through a new method instead. <code>MakeMigrationCommand</code> and <code>StreamLogger</code> each take an optional clock, so a migration&rsquo;s filename and a log line&rsquo;s timestamp can be fixed in a test.</p>

<h3>One missing comment</h3>

<p><code>ParseBodyMiddleware</code> now says why it exists: PHP fills <code>$_POST</code> for a POST only. It also says when it goes: PHP 8.4&rsquo;s <code>request_parse_body()</code> does the same job, multipart included, once the framework&rsquo;s minimum PHP version reaches 8.4.</p>
