<p>0.9.6 kept secrets out of log context, but a reset, verification or address-change link carries its token in the path, and the path went into the request log, any exception report, and nginx&rsquo;s access log exactly as it arrived. Anyone who could read a log could open the link. The application now writes <code>/reset-password/{token}</code> instead, and so does the skeleton&rsquo;s nginx.</p>

<p>Every symbol here is new and every new argument is optional, so this is a patch. It is not marked a security release: every link expires within a day and is spent once used, and reading a log already takes access to the server.</p>

<h3>Upgrading</h3>

<p>Nothing changes until a route asks for it. To take what the skeleton did: add <code>#[\SensitiveParameter]</code> to the <code>$token</code> of each <code>acceptLink</code>; pass <code>PathRedactorInterface</code> to <code>ErrorHandlerMiddleware</code> as its last argument, and bind <code>RequestLoggingMiddleware</code> explicitly with it as the second, because autowiring leaves an optional argument null; and copy the <code>map</code>, <code>log_format redacted</code> and <code>access_log</code> lines from <code>docker/nginx/default.conf</code>. Log lines written before the upgrade still hold whatever tokens they held; any still live stop working once used, or when <code>AUTH_RESET_TTL</code> or <code>AUTH_VERIFY_TTL</code> runs out.</p>

<h3>PathRedactorInterface</h3>

<p>One method, <code>redact(ServerRequestInterface): string</code>, the path as it may be written down. <code>HttpServiceProvider</code> binds it to the <code>Router</code>, which masks every parameter its target marks <code>#[\SensitiveParameter]</code> and leaves the rest of the path as sent. <a href="/docs/routing.html#operations">The log</a> has the details.</p>
