<p>Every command in the framework and in every application extended Symfony&rsquo;s <code>Command</code> directly. That is a minor, and it is the reason for one: a command now implements a Hydra contract, and one class in one new package extends Symfony&rsquo;s.</p>

<p>The argument was never that the console library might be swapped, because it will not be. It was that a breaking change upstream reached applications <em>through</em> Hydra without Hydra&rsquo;s own version number saying anything about it &mdash; which is the promise in <a href="/docs/ethos.html#semver">the version number</a> failing through a side door. Twenty-six classes were exposed to it, growing by one with every generator added.</p>

<h3>Upgrading from 0.6.3</h3>

<p>Every command you have written needs the same four changes. They are mechanical, and the compiler finds all of them.</p>

<ul>
  <li><strong>Imports and base class.</strong> <code>Symfony\Component\Console\Command\Command</code> becomes <code>Hydra\Console\Command</code>, and <code>#[AsCommand]</code> comes from <code>Hydra\Console\Attributes</code>. Drop the <code>parent::__construct()</code>; there is no parent constructor to call.</li>
  <li><strong><code>configure()</code> becomes declarations.</strong> <code>addArgument()</code> and <code>addOption()</code> become <code>arguments()</code> and <code>options()</code> returning <code>Argument</code> and <code>Option</code> values. <code>Option::flag()</code> is present-or-absent and <code>Option::value()</code> carries one, named rather than passed as a mode constant.</li>
  <li><strong><code>execute()</code> returns an <code>ExitCode</code></strong> and takes Hydra&rsquo;s input and output. There is no <code>SymfonyStyle</code> to build: the output is handed in. <code>Command::SUCCESS</code> and <code>Command::FAILURE</code> become <code>ExitCode::Success</code> and <code>ExitCode::Failure</code>, with <code>ExitCode::Invalid</code> (2) for a command that could not run at all as against one that ran and answered no.</li>
  <li><strong>Reads are typed.</strong> <code>getArgument()</code> and <code>getOption()</code> become <code>argument()</code>, <code>option()</code> and <code>flag()</code>, which return a <code>string</code> or a <code>bool</code> rather than <code>mixed</code>. The <code>is_string()</code> guards that used to be necessary around them are now dead code, and PHPStan will say so.</li>
</ul>

<p>In <code>bin/console</code>, <code>new Application(&hellip;)</code> becomes <code>new ConsoleApplication(&hellip;)</code>, <code>addCommands([&hellip;])</code> becomes <code>add(&hellip;)</code>, and the <code>FactoryCommandLoader</code> becomes <code>addLazy([&hellip;])</code> keyed by <em>class</em> rather than by name &mdash; the name is already on the command&rsquo;s attribute, and a second copy at the registration site is free to disagree with it. Add <code>hydrakit/symfony-console</code> to your <code>composer.json</code>; you can drop your direct <code>symfony/console</code> requirement unless something else uses it.</p>

<h3>What a command is now</h3>

<p>A name and a description on <code>#[AsCommand]</code>, so a console can list what it offers without building anything &mdash; which is what lets <code>migrate:fresh</code> appear in <code>list</code> on a machine with no database running. Arguments and options declared as data. A body written against a ten-method <code>OutputInterface</code>, deliberately narrower than what is underneath it: the seam exists to keep the framework off a third-party base class, not to reproduce one.</p>

<p>Symfony&rsquo;s formatter tags went with it. <code>&lt;info&gt;</code> and <code>&lt;comment&gt;</code> are that library&rsquo;s markup language and have no business crossing a contract that does not name it, so <code>admin:check</code> and <code>migrate:status</code> lose some colour in their tables. Colour belongs on the contract if it is wanted back, not in the strings.</p>

<h3>Commands are testable</h3>

<p>The part that pays daily. Testing a command meant driving the console library that ran it, so commands were the least-tested thing in the tree. <code>Hydra\Console\Testing\FakeOutput</code> records what a command said and answers what it asked &mdash; <code>willAnswer()</code> and <code>willConfirm()</code> queue replies, and a question with nothing queued throws rather than defaulting, because a command that asked something the test did not anticipate has taken a branch the test is not covering. Every command test in the framework and the skeleton was rewritten onto it.</p>

<p><code>ArrayInput</code> states what was typed without a terminal, and is not a test double: <code>make:admin</code> composes five generators and has to hand each one its arguments. Build it with <code>ArrayInput::forCommand()</code> rather than the constructor, which is the difference between the two and the bug this release found &mdash; see below.</p>

<h3>Two things found by building it</h3>

<p><strong>Declared defaults.</strong> A parsed command line arrives with declared option defaults already filled in, so a command reading an option it gave a default to never passes a fallback. Built by hand instead, the same read came back empty: <code>make:user</code> worked at a terminal and rejected every role as unknown when composed or tested. <code>ArrayInput::forCommand()</code> fills them in, and <code>Hydra\Console\Testing\InputContractTestCase</code> is published so both implementations are held to the same answers. Nothing in the framework had noticed; an application&rsquo;s test did.</p>

<p><strong>The validator on a question.</strong> The output contract was sized by counting which methods were called, which missed that <code>ask()</code> and <code>askHidden()</code> take a callback that re-prompts on a rejection. PHP passes extra arguments to a userland method without complaint, so <code>make:user</code> silently lost its re-prompting. Measuring names rather than signatures was the mistake; the callback is in the contract now.</p>

<h3>Also</h3>

<p><code>authorization</code> and <code>validation</code> published contracts an application implements &mdash; an ability, a rule &mdash; with no test double and no contract case, which every comparable package ships. Both now have a <code>Testing/</code>: <code>FakeGate</code> decides what it is told and records what it was asked, and <code>RuleContractTestCase</code> holds a rule to the invariants its author will not think to test, the sharpest being that a value arriving from a request body is whatever a client chose to send. A rule that assumes a string and is handed an array is a 500 on a form submission.</p>

<p>Framework suite 1849 tests and 4299 assertions to 1930 and 4444; the skeleton 314 and 830.</p>
