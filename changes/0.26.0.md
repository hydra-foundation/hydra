A form anyone can post now has two spam traps that cost a person nothing: a field people never see, which a bot fills, and a signed start time, which catches the bot that posts the instant it has the page or replays one it fetched long ago. No captcha, no script in the browser, no outside service. Every trapped post is an ordinary validation error, so if a real person is ever caught they see why. The wiki's validation page walks through a contact form end to end, with the per-route rate limit beside it. It is the first piece of the website's contact form, and the comments after it will use the same traps.

It is 0.26.0 because `validation`, `csrf` and `view` gain API: `Rules\Honeypot`, `Rules\SubmittedAfter`, `Honeypot`, `Template::honeypot()` and `PhpView`'s `honeypot:` argument. Nothing was taken away.

## Upgrading

- **The skeleton:** to use the traps, bind `Hydra\Csrf\Honeypot` by hand in `AppServiceProvider` (its limits are optional arguments, which autowiring skips), pass it to `PhpView` as `honeypot:`, and copy the `.form-trap` rule from `public/css/base.css`. Nothing changes for an app that doesn't.

## Validation

- Public forms can trap spam bots without a captcha. `<?= $this->honeypot() ?>` in a form prints a field people never see plus a signed start time (hidden by the app's `.form-trap` class, so a strict `style-src` still hides it), and `rules()` hands back the checks for both: `Rules\Honeypot` (in `validation`) fails when the hidden field has anything in it, and `Rules\SubmittedAfter` (in `csrf`) fails a post sent sooner than three seconds after the page loaded as "too fast", and one older than a day, unsigned or forged as "expired". `error()` picks the message to show above the form. `PhpView` takes the `Hydra\Csrf\Honeypot` as a new optional `honeypot:` argument. `csrf` now requires `hydrakit/validation`.

## The skeleton

- `AppServiceProvider` binds `Honeypot` with the defaults (three seconds, one day, a trap named `website`) and hands it to the view, and `base.css` hides `.form-trap` off screen. No skeleton form uses the traps: login and password reset are the forms a password manager fills.
