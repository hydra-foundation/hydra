<p>Two-factor sign in, optional per account: codes from an authenticator app, recovery codes for a lost phone, and a step between a right password and a signed-in session. The framework ships the pieces and one contract for where they are kept; the skeleton keeps them in its own tables, asks for a code at sign in and has a Security tab to turn it on and off. Building that tab found a bug the account page has had since 0.9.4, fixed here too.</p>

<p>Every symbol here is new, so this is a patch. <code>hydrakit/auth</code> gains a dependency on <code>hydrakit/throttle</code>, for the challenge&rsquo;s budget. Composer brings it in, and nothing already installed has to change.</p>

<h3>Upgrading</h3>

<p>Nothing is required. To offer a second factor, implement <code>TwoFactorStoreInterface</code> over your schema, bind it, and extend <code>TwoFactorStoreContractTestCase</code> to test it. The skeleton&rsquo;s <code>TwoFactorRepository</code> and its migration are a starting point. To take the skeleton&rsquo;s own screens, run <code>php bin/console migrate:run</code> for <code>20260924_000000_add_two_factor_to_users.sql</code>. Its CSP now allows scripts from <code>https://cdnjs.cloudflare.com</code>, which the QR code needs. <a href="/docs/auth.html#two-factor">Two-factor sign in</a> has the details.</p>

<h3>Totp and RecoveryCodes</h3>

<p><code>Totp</code> makes and checks RFC&nbsp;6238 codes with the defaults every authenticator app assumes, and builds the <code>otpauth://</code> link a QR code holds. <code>verify()</code> allows one step of drift either way and returns the step it matched, so the caller can refuse it next time. <code>RecoveryCodes</code> makes ten single-use codes and their hashes, and <code>redeem()</code> says which hashes are left once one is spent.</p>

<h3>TwoFactorChallenge</h3>

<p><code>begin()</code> holds a sign-in for five minutes after a right password, and <code>verify()</code> or <code>recover()</code> finishes it through the guard&rsquo;s <code>login()</code>. Codes are budgeted per account, five in five minutes, and past that a 429. Its store claims steps and spends hashes compare-and-set, which is what stops a code being used twice. It announces <code>TwoFactorChallenged</code>, <code>TwoFactorFailed</code> and <code>RecoveryCodeUsed</code>, and <code>LogAuthEventsListener</code> logs them. <code>ArrayTwoFactorStore</code> is the fake.</p>

<h3>SessionGuard</h3>

<p><code>validate()</code> returns the user a username and password name without signing them in, with the same events and the same cost as <code>attempt()</code>, which is now <code>validate()</code> then <code>login()</code>. It is not on <code>GuardInterface</code>, since adding a method there would break every other guard, so <code>AuthServiceProvider</code> also binds <code>SessionGuard</code> by its class, to the same shared instance.</p>

<h3>In the skeleton</h3>

<p>Two columns and a table for the secret, the last used step and the recovery codes. The secret is encrypted under the row&rsquo;s id, and a secret that no longer decrypts throws rather than turning the second factor off. A right password on an account with one goes to <code>/two-factor</code>. Settings &rarr; Security sets it up with a QR code and the key as text, confirms with a code and the password, and shows the recovery codes once. New codes, and turning it off, take the password and a code from the app or a recovery code. Each change is audited, and the owner is mailed when it is turned on or off and when a recovery code is used. <code>public/js/qr.js</code> draws the QR code with a pinned, SRI-checked library it fetches only when a page has one.</p>

<h3>The email form</h3>

<p>The account page&rsquo;s change-of-address form, new in 0.9.4, never submitted in a browser. It carried a hidden field named <code>form</code>, and a control named after a property of its form replaces that property: <code>form.form</code> was the input. htmx 4 finds a POST&rsquo;s form through <code>elt.form</code>, so it passed the input to <code>new FormData()</code>, which threw. The flow tests post directly and never ran htmx. The field is now <code>intent</code>, and a test refuses any field named after a form property.</p>
