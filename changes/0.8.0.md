<p>0.7.2&rsquo;s audit against <a href="/docs/ethos.html#checking">the ethos</a> found two things it could not fix without breaking something. This release fixes both. Five command classes move to new namespaces, and <code>ArrayStore</code>&rsquo;s constructor stops accepting a closure. Either one takes something away from a caller on <code>^0.7</code>, and in 0.x the middle number is the one that says so, which is why this is 0.8.0. Composer will not install it until you widen the constraint to <code>^0.8</code>.</p>

<h3>Upgrading</h3>

<p>Five imports in <code>bin/console</code> change, and nothing else about the commands does: same names, same options, same constructors.</p>

<p><code>new ArrayStore(fn () =&gt; ...)</code> becomes <code>ArrayStore::withClock($clock)</code> or <code>new ArrayStore($clock)</code> with any PSR&#8209;20 clock, <code>FrozenClock</code> in a test. Nothing in the framework or the skeleton passed a closure; <code>withClock()</code> is unchanged, so code that moved onto it in 0.7.2 does not move again.</p>

<h3>The package that owns a command ships it</h3>

<p><code>hydrakit/console</code> required <code>http</code> and <code>database</code> for five commands, so an application that only wanted commands installed a database layer. Now <code>migrate:*</code> lives in <code>database</code> and <code>route:cache</code> in <code>http</code>, and each requires <code>console</code>. That is how <code>admin</code> already shipped <code>admin:check</code>. <code>console</code> itself requires nothing from Hydra. <code>make:migration</code> stays in <code>console</code>: it writes a file with a timestamp and never opens a connection.</p>

<p>The test that held every shipped command to its declarations could not stay in <code>console</code> once the commands left, so it is published as <code>Hydra\Console\Testing\CommandContractTestCase</code>. Three packages run it now, and <a href="/docs/console.html#testing">a command of your own</a> can too.</p>

<h3>A filter the source advertises is a filter it runs</h3>

<p><code>admin:check</code> compares a module&rsquo;s <code>-&gt;filterable()</code> fields with its source&rsquo;s description, but the description is only a declaration. A source whose own conditions never matched the key it named passed that check, added no clause to the query, and answered a filtered request with the whole table. The source contract case now asks for <code>filterValues()</code>, a value for each column the source filters by, and checks that each value narrows the list. <code>make:source-test</code> writes the hook for you. <a href="/docs/module.html#tests">Building a module</a> has the example.</p>

<p>The first run caught all three of the skeleton&rsquo;s filtering sources with filters no test had ever run. It also caught a users fixture in which every row had the same role, so a role filter that worked could not be told apart from one that did nothing.</p>

<h3>Every file parsed on every PHP</h3>

<p><code>bin/syntax.sh</code> runs <code>php -l</code> over every package, the <code>bin</code> scripts and the tests, and CI runs it on each PHP version the framework supports. PHPUnit only compiles the files a test loads, so a file with PHP&nbsp;8.4 syntax that no test loaded passed on 8.2. <code>new X()-&gt;method()</code> once reached <code>AdminController</code> that way.</p>
