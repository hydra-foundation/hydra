<p>The second half of what 0.9.1 started. A new package, <code>hydrakit/queue</code>, lets a request hand work to later: the job is pushed during the request and handled within the minute by the scheduler that is already running. It adds only new classes, and the one change to an existing class is a fix, so this is a patch.</p>

<h3>Upgrading</h3>

<p>Nothing is required. To use the queue, require <code>hydrakit/queue</code>, create the <code>jobs</code> and <code>failed_jobs</code> tables, bind <code>QueueInterface</code> to a <code>DatabaseQueue</code>, and schedule <code>drain(Worker::class)</code>. The skeleton does all of it. <a href="/docs/queue.html">The queue</a> has the tables and the bindings.</p>

<h3>A queue that rides on the scheduler</h3>

<p>A job implements <code>JobInterface</code>, is built by the container, and is handed the payload it was pushed with. The payload is stored as JSON, so it holds plain data only; an object in it is refused with the key where it was found. <code>Worker</code> is a scheduler batch that claims twenty jobs at a time. It deletes a job that finishes, retries one that throws after 10 and then 60 seconds, and moves it to <code>failed_jobs</code> with its exception after the third failure. The attempt is counted when the job is claimed, so a job that kills its worker still runs out of tries. A claim whose worker died is taken again after fifteen minutes. On MariaDB a claim skips rows another worker has locked instead of waiting on them. <code>FakeQueue</code> and <code>QueueContractTestCase</code> ship with it.</p>

<h3>Fixed</h3>

<p><code>MigrationRunner</code> failed any migration file with more than one statement on MariaDB, reporting a syntax error near the second. It was written to run and check every statement in a file, but a PDO built with <code>ATTR_EMULATE_PREPARES</code> off, as the skeleton&rsquo;s is, takes one statement per query. The runner now turns emulation on for the length of that one query and restores it afterwards.</p>

<h3>In the skeleton</h3>

<p>Migrations for <code>jobs</code> and <code>failed_jobs</code>, a <code>QueueInterface</code> binding, and the worker on the schedule every minute with a five&#8209;minute budget. Nothing is queued yet; the skeleton&rsquo;s own mail is the first thing to move. <code>TestApp</code> binds its SQLite handle as <code>PDO</code> as well as the connection, so nothing in the suite that asks for the raw handle reaches MariaDB.</p>
