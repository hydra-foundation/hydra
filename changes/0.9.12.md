<p>Until now, the queue could only be seen from a terminal, and a failed job could not be deleted without retrying it. The admin now shows it: a Jobs list of what is waiting, a Failed jobs list with the whole trace a click away, and a dashboard card counting both. To get there the admin learned actions, buttons that run a class of yours, which any module can use.</p>

<p>Everything here is new, so this is a patch. One small change in behaviour is covered under Upgrading.</p>

<h3>Upgrading</h3>

<p><code>Field::datetime()</code> now reads a value made only of digits as unix seconds, on every screen and in an export. Such a value used to print as the raw number. The one exception: an eight-digit <code>YYYYMMDD</code> string used to be read as a date, and is now read as seconds, so a column stored that way should use <code>Field::text()</code>. <code>DATETIME</code> columns are unaffected.</p>

<p>To get the queue screens in an application built on the skeleton, copy <code>src/Admin/Modules/JobsModule.php</code>, <code>FailedJobsModule.php</code>, their two sources, <code>src/Admin/Actions/</code> and <code>src/Admin/Widgets/QueueWidget.php</code> with its view, then register the modules and the widget, and add <code>queue:forget</code> and <code>queue:flush</code> to <code>bin/console</code>.</p>

<h3>Admin actions</h3>

<p><code>ActionScreen::row()</code> and <code>ActionScreen::module()</code> declare a button that posts and runs a <code>RowActionInterface</code> or <code>ModuleActionInterface</code>. The returned text is the notice, <code>WriteRejected</code> refuses, and a done action announces <code>ActionTaken</code>. <code>when()</code> hides a row&rsquo;s button where it does not apply, and <code>DeleteScreen</code> takes it too, along with <code>labelled()</code>. <code>Definition::gone()</code> answers a stale View or Edit link with the list and a message instead of a bare 404. <a href="/docs/admin.html#actions">Actions</a> has the details.</p>

<h3>The queue</h3>

<p><code>DatabaseQueue</code> gains <code>cancel()</code>, <code>forget()</code> and <code>flush()</code>, and the console gains <code>queue:forget</code> and <code>queue:flush</code>. <a href="/docs/queue.html#failed">Failed jobs</a> has the details. In the skeleton:</p>
<ul>
  <li>Queue &rarr; Jobs lists waiting and held jobs, and cancels a job no worker has claimed.</li>
  <li>Queue &rarr; Failed jobs lists failures by their one-line reason, with Retry, Retry all and Clear all. Each writes one audit line, without the payload or the trace.</li>
  <li>The dashboard&rsquo;s queue card counts waiting, held and failed jobs for admins.</li>
</ul>
