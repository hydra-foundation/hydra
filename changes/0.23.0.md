The first piece of M3, Publishing. A template links a stylesheet or script with `$this->asset('/css/app.css')` and gets a name carrying the file's hash, `/css/app.5267ab8c9f.css`; the skeleton's nginx keeps those names for a year without asking again, and an edit reaches every browser on its next page because the name changes with it. There is no build step and no manifest: the hash is worked out as the page renders, about a fifth of a millisecond for the skeleton's sixteen files. The skeleton's layout links everything this way, vendor files included, and a test fails the build on a link that skips it.

It is 0.23.0 rather than a patch because `hydrakit/view` exports something new. Nothing was taken away, and `Assets` is optional: an application that does not pass one to `PhpView` renders exactly as before.

## Upgrading

- **The skeleton:** `docker/nginx/default.conf` changed: replace your copy's
  static rules for `/css/` and `/js/` with the skeleton's, then
  `docker restart` nginx (a reload keeps the bind-mounted file's old copy).
  Without the new rule, a fingerprinted name is a 404.
- **Views:** Optional. To fingerprint, pass `assets: new Assets($publicPath)` to
  `PhpView`, link each stylesheet and script through `$this->asset()`, and serve
  the hashed names as the skeleton's `docker/nginx/default.conf` does: a
  `location` that strips the hash, marked immutable, and no `^~` prefix block
  for `/css/` or `/js/` in front of it.

## Views

- `Assets::url('/css/app.css')` returns `/css/app.3f2a1c9b0e.css`, the hash
  being the file's bytes, so a stylesheet or script can be cached for a year and
  an edit still reaches every browser on its next page view. It is worked out on
  each request, with no manifest and no build step. Templates call
  `$this->asset('/css/app.css')` once `PhpView` is given an `Assets` (the new,
  optional `assets:` argument); without one it throws, naming the fix. A path
  that is not a file under the public directory throws `AssetNotFound`, saying
  which rule it broke.

## The skeleton

- `views/layouts/base.php` links every stylesheet and script through
  `$this->asset()`, vendor files included, and the hand-bumped `?t=` on
  `app.css` is gone. `AssetLinksTest` fails on a link that skips `asset()` or
  names a missing file, with the error that says which.
- nginx serves a fingerprinted name from its plain file, marked immutable for a
  year; a 404 on one is not, so a file deployed a moment late is not missing
  for a year. Plain `.css` and `.js` names are `no-cache`, so a link that
  skipped `asset()` still sees an edit. The `^~` blocks for `/css/` and `/js/`
  are gone: a prefix match stops nginx trying any regex location after it.
- `AGENTS.md` says how to link a stylesheet or script.
